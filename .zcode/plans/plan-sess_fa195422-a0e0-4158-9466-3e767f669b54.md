## 深层修复目标

让 `inventory_item_id` **路径无关**，使同一逻辑资产在 active 路径和 disabled 路径下拥有同一个 id。彻底消除 `executor.rs` 里 `post_by_logical_key` fallback 的需求（保留为防御性兜底，但路径漂移场景不再触发）。

## 设计

### 新的 source_identity 语义

```
source_identity = origin_namespace_for(item)
```

按 source_origin 派生（复用 `ensure_managed.rs:511 origin_namespace_for_item` 的语义）：

| source_origin | origin_namespace | 例 |
|---|---|---|
| `Standalone` | `"standalone"` | claude/opencode user/project skill、command |
| `NativeConfig` | `"standalone"` | codex/opencode MCP（config 文件）、codex plugin |
| `PluginComponent` | `"plugin:{plugin_id}"` | plugin 下的 skill/command |

id 材料 = `target | scope_id | source_identity | native_id`，例：
- `claude | user | standalone | hyperframes`（standalone skill）
- `claude | user | plugin:myplug | my-skill`（plugin 内 skill）
- `codex | user | standalone | good-api`（codex MCP）

**关键不变量**：同一逻辑资产在 active/disabled 路径下产出**相同 id**；不同逻辑资产（不同 target/scope/origin/native_id）**绝不撞 id**。

### `source_path` 字段保留绝对路径

不动 `PortableInventoryItemDto.source_path`——UI 显示、executor 物理移动、ensure_managed namespace 提取都依赖它。

## 改动清单

### 1. `src-tauri/src/agent_hub/portable_inventory/scanner.rs`

**1a. `discovered_to_item`（line ~1259-1298）— 核心**
- 把 `source_identity = source_path.clone()` 改为按 `disc.origin.origin_kind` + plugin_id 派生逻辑源：
  - `Plugin` → `format!("plugin:{}", plugin_id)`（plugin_id 从 `disc.origin.parent_plugin_id` 直接取，或 fallback 用 `infer_plugin_root` + `plugin_id_from_path`）
  - `Native | Compatibility | LegacyStandalone` → `"standalone"`
- `source_path` 字段保持绝对路径不变（line 1376 `source_path: Some(source_path)`）
- `parent_plugin_inventory_item_id`（line 1288）派生也走同一逻辑源：plugin 本体的 source_identity 用 `"standalone"`（plugin package 不嵌套在另一个 plugin 里），native_id 用 plugin_id

**1b. `scan_plugin_packages`（line ~680-770）**
- plugin 包本体的 `source_identity`：保持当前用 `root.display()` 还是改？plugin 包不会被 disable 移动（codex plugin 是 config-based、claude plugin 无 disabled 路径概念），所以路径已经稳定。**为一致性也改成逻辑源** `"standalone"`（plugin package 的 source_origin 是 Standalone），native_id 是 plugin_id。

**1c. seen 去重策略（最高风险）— 关键改动**
- 当前 `seen_ids: BTreeSet<String>` 去重维度是完整 id
- 改后 active/disabled 同 id 共存，必须改去重逻辑
- **方案**：在 `scan_portable_inventory_facts_query`（line 281）把 `seen_ids` 改成 `BTreeMap<String, usize>`（id → items 里的 index），或在 `discovered_to_item` 内遇到已存在 id 时按优先级合并：
  - 若已存在 item 的 `actual_enabled == false`（disabled），跳过新发现的（保留 disabled）
  - 若已存在 item 的 `actual_enabled == true`（active），新发现的是 disabled → **替换**为 disabled 版本（保留 disabled）
  - 简言之：**disabled 永远赢**（用户最近意图）
- 实现：`discovered_to_item` 签名从 `&mut BTreeSet<String>` 改为 `&mut BTreeMap<String, PortableInventoryItemDto>`（已存在 item 的索引），遇到冲突按上面规则合并/替换，返回值改为 `Option<(insert_or_replace_op)>`，调用方根据 op 更新 items。
- 或更简洁：返回 `DiscoveryOutcome { New(item) | ReplaceExisting(item) | Skip }`，调用方执行

**1d. 文档更新**
- `models.rs:385 inventory_item_id` 函数 docstring：说明新的 source_identity 语义（路径无关、逻辑源）

### 2. `src-tauri/src/agent_hub/portable_inventory/ensure_managed.rs`

- `origin_namespace_for_item` 当前是私有函数。**导出（pub(crate)）并在 scanner.rs 复用**，确保 id 算法与 canonical 跟踪用同一套 namespace 语义。
- 注意：`origin_namespace_for_item` 接收的是 `&PortableInventoryItemDto`（已构造好的 item），scanner 里我们需要在构造 item **之前**派生（用 `DiscoveredPortableAsset`）。所以**抽象一个底层函数** `origin_namespace_from_parts(source_origin: PortableInventorySourceOrigin, source_path: Option<&str>) -> String`，让 `origin_namespace_for_item` 和 scanner 都用。

### 3. `src-tauri/src/agent_hub/portable_actions/executor.rs`

- `post_by_logical_key` + `resolve_post_item`（line 444-542）：改后路径漂移场景不再触发，但**保留作为防御性兜底**（应对 scope_id 因 hub_project_id 重映射而变的其他漂移场景）。更新注释说明现在主要兜底 scope 漂移。
