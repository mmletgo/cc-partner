# web/ - React 前端

> 根层概览、组件清单、token/复用规范见仓库根 `AGENTS.md`。后端协议/端口/CLI 见 `src-tauri/CLAUDE.md`。跨平台 CI / smoke 矩阵见 [`docs/development/testing.md`](../docs/development/testing.md)。

## 概述

基于 React + TypeScript + Vite 的前端界面，宿主为 **Tauri 2**，桌面主界面通过 `invoke()` IPC 调用 Rust 后端命令（`src-tauri/`）。`/mobile` 普通浏览器 SPA 通过同源 HTTP 调用后端移动端/Workbench routes。

## 开发命令

- `npm run dev` — 启动 Vite 开发服务器（端口 5173）
- `npm run build` — 打包到 dist/（`tsc -b` 类型检查 + vite 构建；类型检查入口，**不要**用浮动 `npx tsc`）
- `npm run lint` — ESLint 检查
- `npm run check:css-tokens` / `npm run check:tokens` — design token 合同（权威实现 `web/scripts/check-css-tokens.mjs`；根 `scripts/check-css-tokens.mjs` 仅为 thin wrapper）：扫描 `src/**/*.css` 的 `var(--name)`，语义 token 必须在 `styles/tokens.css` 的 `:root` 定义；颜色/阴影类 token 必须浅/深双份；仅 allowlist 运行时结构变量 `--prompt-panel-left` / `--prompt-panel-top` / `--git-graph-color`；通过打印 `CSS token contract passed`（exit 0），失败打印 `file:line --token`（exit 1）。CI quality 在 build 前执行（`check:tokens`）。fixture：`node --test scripts/check-css-tokens.test.mjs`；CLI `node scripts/check-css-tokens.mjs --self-test` 等价。
- `npm run check:bundle` — 拆包合同（权威实现 `web/scripts/check-bundle-contract.mjs`；根 `scripts/check-bundle-budget.mjs` 仅为 thin wrapper）：读取 Vite 写出的 `dist/.vite/cc-bundle-contract.json`，对 `main`/`mobile` entry 沿静态 `imports`（排除 `dynamicImports`）求 JS 闭包 gzip，并加上入口 HTML 直接引用的 stylesheet（`entryStyles` / dist `index.html`·`mobile.html` 的 `<link rel="stylesheet">`）gzip；**最终硬顶**（baseline 不得抬高）：desktop main ≤ 320 KiB、mobile initial ≤ 280 KiB、单 lazy JS chunk ≤ 700 KiB、全部 runtime JS gzip ≤ 1,400 KiB、dist `*.map` raw 合计 ≤ 2 MiB 或无 map。可选 baseline ratchet（`web/scripts/bundle-budget-baseline.json` 与根 `scripts/bundle-budget-baseline.json`）：对各指标取 `min(baseline, final)` 禁止增长；失败诊断打印 actual/baseline/final/ceiling 与 top 5 chunks。报告分项 `js=`/`css=`；mobile initial 禁止 `@xterm/*`、`@tiptap/*`、`@uiw/react-codemirror`、`codemirror`/`@codemirror`、`recharts`。通过打印 `Bundle contract passed`。CI quality 在 build 后执行。fixture：`node --test scripts/check-bundle-contract.test.mjs`；CLI `--self-test` / `--write-baseline`。生产 `sourcemap` 默认 `false`；仅 `CC_PARTNER_SOURCEMAP=1` 生成 `hidden` map（无 `sourceMappingURL`）。重型边界：`WorkbenchFileWorkspace` 动态加载 Code/Markdown/HTML 编辑器；`MobileWorkbench` 动态加载 terminal/files/automation/browser/git/worktrees/prompt/settings 面板（Projects/Attention shell 同步）；Health 路由 lazy 且 StatsChart/recharts 不得进入 eager App 图
- `npm run check:i18n` — 生产 TSX i18n 合同（`scripts/check-i18n-jsx.mjs`）：typescript AST 扫描 `src/**/*.tsx` 的 JSXText 与 `title/aria-label/placeholder/alt` 字符串字面量；含中文/拉丁字母的文案必须来自 `t()` 或有限品牌 allowlist（`cc-partner`/`Claude Code`/`Git`/`GitHub`/`HTML`/`JSON`/`SQLite`/`tmux`/`WSL` 与纯标点）；排除 `.test`/`.stories`/`DesignSystem`/`testing`；诊断格式 `file:line:column`。CI quality 在 build 前执行。fixture：`node --test scripts/check-i18n-jsx.test.mjs`；zh/en key 对等：`npm test -- localeParity`
- `npm test`（`vitest run`）— 单次跑全部单元测试；Vitest 按 `vitest.config.ts` 的 `include: ['src/**/*.test.{ts,tsx}', 'tests/support/**/*.test.ts']` 自动收集（E2E `*.spec.ts` 排除）。按路径过滤：`npm test -- src/pages/Workbench` 或 `npm test -- attention`；harness 合同：`npm test -- tests/support/backendHarness`；故障分类与恢复策略：`npm test -- src/lib/faultRecovery`

### 测试环境约定

- Vitest 默认 **Node environment**（`vitest.config.ts` 中 `test.environment: 'node'`），不全局启用 jsdom
- 只有真正访问 DOM 的测试文件，才在文件顶部显式声明 `// @vitest-environment jsdom`
- CI 只用 `npm ci` 安装锁定依赖；**禁止** 带 `--yes` 的浮动 `npx` runner，也**禁止**文档/脚本推荐按文件手敲的 `npx` + `tsx` 单文件测试入口——一律走 `npm test` / `npm run test:e2e`
- 稳定命令四条：`test` / `test:unit:watch` / `test:e2e` / `test:all`（与 `package.json` 一致）

### 前端约束摘要（本目录必守）

- **组件 / token / i18n**：颜色间距圆角阴影 100% `tokens.css`；禁止未定义语义 token 或为错误名加 alias（如 `--bg-2`→`--bg`、`--fg-muted`→`--muted`/`--meta`、`--warning`→`--warn`）；`globals.css` 在 `prefers-reduced-motion: reduce` 下对 animation/transition duration **有意使用 `!important` 全局归零**，确保组件级 transition 无法重新引入动效；产品接受「无例外」a11y 语义；用户可见文案走 `src/i18n`；详见根 `AGENTS.md` §3–§5 与本文 i18n 节
- **Hooks 顺序**：所有 hooks 与 Workbench controllers 必须在 early return 之前（根规则 + `AGENTS.md` §5.8）
- **巨型页 controller/view 拆分**：Settings → `useSettingsController` + General/Sync/Dependencies/AI/About pure panels（views 无 API；另有既有 Health/Automation panels）；桌面 Orchestrator → `useOrchestratorController` + Board/Outbox/TaskDrawer/CreateDialog views；Mobile Automation → `useMobileAutomationController` + TaskList/TaskDetail/CreateDialog/Outbox；禁止第八个 Workbench 聚合 controller；`Workbench.tsx` ≤1200 行；手动 a11y smoke 建议 VoiceOver/NVDA 覆盖 Dialog/Drawer/Attention 行/终端 tabs。**已接受的 M3 residual**：`useSettingsController` / 桌面 Orchestrator controller / mobile automation controller 仍是大型编排模块（结构债，非行为 bug）；进一步按域拆 controller 延后，不在 S4 panel 文件化范围内。
- **Workbench 页面合同**：`Workbench.tsx` ≤ **1200 行**；域逻辑在 `controllers/` 七个 hook；禁止页面直接 `workbenchApi.(sessions|files|worktrees|git)` 或 `listen('workbench:terminal-status|merge-progress')`
- **Attention**：Provider 共享 snapshot；成功业务动作立即 invalidation；10s 可见轮询兜底；列表只导航不动作
- **Runtime 显示缓存**：桌面 `useOrchestratorRuntimeSnapshot` 与移动 `mobileRuntimeSnapshotStore` **进程内 Map 彼此独立**；只缓存 remote **live** 成功；不写 localStorage/SQLite；缓存不驱动 task action / scheduler

## 架构

- **业务类型域拆分**: `src/lib/types/` 按 `core` / `settings` / `workbench` / `orchestrator` / `attention` 拆分；`src/lib/types.ts` 仅为兼容 barrel（`export * from './types/index'`），旧路径 `@/lib/types` 继续可用。域文件只允许 import upstream `./core`（或其它相对域路径），禁止回指 `../types` 或 `@/lib/types`。contract：`npm test -- typeBarrel`。
- **API 客户端**: `src/api/client.ts` — 桌面端基于 `@tauri-apps/api/core` 的 `invoke` 薄封装；Rust 后端 reject 的错误（`{error:"消息"}`）经 `normalizeError` 规整为带 `message` 的 `Error`。关键 DTO 在 IPC/HTTP 边界经 `src/lib/runtimeSchema.ts`（薄门面，实现在 `runtimeSchemaPrimitives.ts`）组合式 decoder + `src/lib/schemas/*` 域 schema **fail-closed** 校验：`invokeDecoded(command, args, decoder)` 与 decoder-aware `getJson/postJson`（可选 `decoder`，**仅成功 body** 解码；错误体不走 schema）。未知额外字段允许前向兼容，必填/枚举/有限数严格；legacy default 仅在对应 schema 字段显式声明；`ContractDecodeError` 只暴露 contract/path/actualKind，禁止序列化 payload。已覆盖 protocol health/capabilities/P2pErrorEnvelope、Attention snapshot、Orchestrator task/runtime/outbox/task-view/evidence/refresh 与 mutation task-view 路径、Transfer task/send/cancel/progress/status、Workbench project/worktree/session/path/save/fileNode/openFile（含 remote openProject、session rename、listDir/open）、AppConfig/Permissions。`/mobile` 浏览器端使用 `src/api/workbenchHttp.ts` 的同源 HTTP JSON helper 和 `src/api/mobile.ts` 的 access-info API，错误优先读取 JSON `error/message`。
- **故障分类与恢复**: `src/lib/faultRecovery.ts` — 纯策略模块：`classifyTransportFault` / `planFaultRecovery` 将 `networkOffline|timeout|malformedJson|permissionDenied|conflict|dbBusy|lanBoundaryRejected|crossSiteRejected`（及 Error-like `code`/`name`/`message`）映射为 typed 分类（稳定 code、retryable/showRetry、cachePolicy=`keepStale|clear|none`、错误路径 `allowOptimisticCommit:false`）；offline/timeout 保留可用缓存并标 stale，malformed fail-closed 清缓存，LAN/跨站拒绝不写 cache 且不发明 identity auth。`createTerminalFaultBridge` 提供 disconnect 归零 listener、reconnect 精确恢复 baseline、断线输入不入账与 replay 幂等。无生产 env 故障开关；L0 合同 `npm test -- src/lib/faultRecovery`。harness 导出 `FAULT_PROFILE_CODES` / `faultProfileCode` / `createFaultError` 与分类表对齐；`malformedJson` 在 invoke 上 **resolve** `{notAValidDto:true}`（生产 `invokeDecoded`→`ContractDecodeError`），fetch 仍返回非 JSON body `{not-json`。**生产接线**：`useAttention` load catch 用 `plan.keepCache` 映射 `loadFailed.hasSnapshot`；`Transfer.loadTasks` 按 `plan.clearCache` 清空/保留 tasks（错误优先稳定 code）；`isRemoteWorkbenchOfflineError` 优先 `NETWORK_OFFLINE` typed 分类，中文「远端设备不在线」仅 legacy 回退。
- **MobileAccessCard**: `src/components/domain/MobileAccessCard` 统一展示局域网 `/mobile` 访问链接和二维码，由 `AppShell` 左下角主题按钮右侧的手机按钮经共享 `Dialog` 模态复用；Settings dependencies tab 与 Workbench 右侧检查器不要再内嵌该卡片，也不要在页面内重复生成二维码或复制逻辑；Tauri 桌面环境通过 `get_mobile_access_info` invoke 获取数据，普通浏览器环境才 fallback 到 `/api/mobile/access-info`。警告区固定渲染 `mobileAccess.warning`：中文“同一可达网络中的任何设备均可读取、写入和执行；系统不验证调用者身份”，英文等价声明；禁止“安全/已认证/可信设备”等措辞，不引入 mode UI。
- **Mobile SPA**: `mobile.html` + `src/mobile/` — 独立 `/mobile` Vite 入口，构建产物引用根路径 `/assets/*`，由 Rust fallback 精确服务对应 frontendDist asset；入口加载 tokens/reset/i18n，根组件创建 terminal buffer store、订阅 `/api/workbench/events` NDJSON，并渲染移动 Workbench shell；手机竖屏导航默认收起，用户需要时通过顶部按钮打开（`MobileWorkbenchShell` 窄屏导航走共享 `Drawer side="left"` 原语，禁止手写 backdrop/role=dialog；宽屏固定 rail 在 Drawer 外常驻），默认面板为 projects（有待处理事项时也不自动抢占），主面板顺序固定为 projects/attention/automation/terminal/browser/files/git/worktrees/prompt/settings；attention 为导航第二项「待处理」并显示与桌面相同的 badge 规则，不在顶栏永久增加第二个 attention 按钮。`MobileWorkbench` 挂载后通过 `httpWorkbenchTransport.projects.list()` 读取最近项目；`kind === "local"` 和 `kind === "remote"` 的项目都可选择，并并行加载 `worktrees.list(project.id)` 与 `sessions.list(project.id)`，成功后进入 terminal；remote shortcut `aria-disabled` 提示不可用；active worktree 优先主工作区、否则首项，active session 优先 `matching worktree && running`、任意 matching worktree、任意 running、首项，并把 active project/worktree/session 名称传给 shell 状态栏；worktrees 面板用 ## i18n 国际化

- **库**: react-i18next + i18next，初始化在 `src/i18n/index.ts`（`declare module` 类型扩展，`t()` 的 key 编译期校验，拼错即 tsc 报错）
- **命名空间**: `common`（动作/状态枚举/方向，跨页共享）、`nav`、各页面一个（home/attention/prompts/ccHistory/transfer/devices/scratchpad/promptOptimizer/claudeMd/welcome/settings/ssh/health/workbench/orchestrator）
- **写法约定**（i18next v26 类型硬要求）:
  - 组件内 `const { t } = useTranslation([用到的所有ns数组]);`，所有 `t('ns:key')` **带 ns 前缀**
  - 模块级 helper 接收 `t: TFunction<'ns'>`，内部调用**省略 ns 前缀**
  - 插值 `{{var}}`；英文复数 en `{key}` + `{key}_other`，zh 只 `{key}`
- **切换/持久化**: `useLanguage` hook（localStorage `cp-lang` + `cp-lang-change` 自定义事件 + `storage` 事件跨标签/多窗口同步）；首次按系统语言推断
- **术语保留英文**: Prompt / GitHub / KB·MB 等在 en/zh 资源都保留英文
- **DesignSystem 页**: dev-only，不纳入 i18n（保持英文）
- **AST 合同 / 对等**: `npm run check:i18n` 禁止生产 TSX 硬编码 letterful JSXText 与 title/aria-label/placeholder/alt 字面量；`npm test -- localeParity` 要求 zh/en namespace 与 leaf key（复数后缀归一化后）对等；新增 key 必须中英同提交
- **新增页面文案**: 在 `src/i18n/locales/{en,zh}/<页ns>.json` 加 key + 组件 `useTranslation(['<页ns>','common'])` + `t('<页ns>:key')`；改完 `npm run check:i18n && npm test -- localeParity && npm run build`（tsc 校验 key）
